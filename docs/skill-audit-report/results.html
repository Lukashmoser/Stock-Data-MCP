Stock-Data MCP results

With the stock-data tools on, the skills scored 237 of 240 against 221 without them. The gain came from freshness, sourcing and a few accuracy misses. The difference showed in 11 of 24 tests and was zero on the control. Without the tools, Claude still got most figures right from web pages and filings, but it took far more fetches, leaned on memory more often, and sometimes used stale prices.

Where the MCP made a difference

Freshness (+5) and sourcing (+6) account for most of the gap. On accuracy, arm A was usually right too, because the latest filings and prices are on the open web. It got there with three to ten times as many fetches, and it fell back on memory or stale caches more often.

  • ER-01 +3
    Catalyst calendar. Arm A computed 52-week positions from closing-price ranges off an aggregator, so all eight "% of range" figures fell outside tolerance. It also missed later 8-Ks for GOOGL and NVDA because EDGAR was blocked from the workspace.
  • ER-10 +3
    Sector overview. Arm A took every Apple figure from memory and used a different META capex definition marked High confidence. Arm B built all 33 figures from 52 tool calls and no web search.
  • FA-02 +3
    Competitive analysis. Arm A's META market cap came from a cached Google Finance page dated 09-25, and its RDDT cap was 3% off. Arm B's were exact.
  • FA-05 +2 · FA-07 +2
    Audit and data cleaning. Both arms caught every planted error. Arm A checked FY2023–25 historicals from memory, and in FA-07 it "corrected" two values that were already right (1-unit rounding). Arm B checked every cell against XBRL.
  • ER-02, ER-04, ER-07, FA-06, FA-13 +1
    Smaller gaps: memory-sourced post-earnings moves (ER-02), a day-old MSFT price (ER-07), a one-day-old HY spread (FA-06). For FA-13, arm A's generated skill couldn't parse the real tool output because the tools were hidden while it was written.
  • FA-09 −2
    The only test arm A won, and the cause is an MCP bug. Arm B reported ZM's 10-15 move as +5.6% with High confidence; the real move was +4.28%, because get_quote returned a wrong prev_close that day.
  • Ties (13)
    ER-03, ER-05, ER-06, ER-08, ER-09, ER-11, FA-01, FA-03, FA-04, FA-08, FA-10, FA-11, FA-12 scored the same. Effort did not tie: ER-05 arm A needed 23 SEC page fetches against arm B's 4 tool calls, FA-03 45 fetches, FA-12 18 against 2.

Issues found in the MCP

These are for the stock-data repo. None caused a tool error; each returned plausible-looking data.

  • Bug
    get_quote prev_close wrong on 2026-10-15, so change and change_pct were wrong for every ticker checked. QQQ showed +0.82% on a −0.13% day; MSFT +1.65% against +1.08%. Price and market cap were correct. Verified against get_price_history. The value was right on 10-13 and 10-14.
  • Bug
    Stale 52-week fields. On 10-13, AAPL's quote showed a 348.15 day high but kept 345.34 as the 52-week high. Consider deriving 52-week high/low from price history instead of trusting the quote field.
  • Gap
    D&A missing for MSFT, GOOGL, ORCL and AMD, so EBITDA (comps, DCF, LBO) needed a filing or the web in both arms. Debt lines missing for ORCL, ADBE, QCOM, IBM and NFLX (ER-09 arm B patched six from sec.gov).
  • Gap
    Derived Q4 quarters return null EPS and share counts. Every Q4-sensitive test had to compute them (ER-07, FA-11).
  • Gap
    free_cash_flow includes discontinued operations. For AMD FY2025 the tool gives 6,735 against the company's 5,519.
  • Gap
    get_filings returns 10-K/A ahead of the original 10-K by default (AMD). Large-cap filing lists are dominated by Forms 4 and 144, so a 40-row call can miss every periodic filing (META in the FA-13 follow-up).
  • Info
    Arm B found the tools on its own in 23 of 23 market-data tests, and correctly didn't call them on the FA-10 control. Several runs hit transient bridge disconnects on their first calls and recovered on retry.

The fixture tests show the MCP's limits clearly. The formula errors and planted inconsistencies were caught equally by both arms. The MCP helped only on checks against external data, and even there arm A usually got the answer from earnings releases.

FA-13 follow-up: did the generated skill work?

Each arm's weekly-watchlist-review skill was installed and run on AAPL, NVDA and META with the tools on. Neither produced a fully correct table without help, but arm B's came much closer.

Arm A's skill was written without seeing the tool schemas. Run as written, it silently returned n/a for 1W, 1M and 52-week position on every name, because its parser didn't recognise the real get_price_history output shape. It was correct only after the reshape step its own reference doc describes.

Arm B's skill ran exactly as written: correct tool names and parameters, all numbers right. Its one wrong cell was META's latest SEC filing, left blank and unflagged, because 40 rows of Forms 4/144 crowded out every periodic filing.

Method and deviations

  • Setup
    Each run was a separate agent with no shared memory, not a fresh chat. Arm A was told the stock-data tools were off rather than having them removed, so it knew they existed. It never called them, which the judges confirmed from run logs and work folders. Canned replies C1–C3 were given up front, since agents can't pause.
  • Timing
    Runs spanned three trading days because of usage-limit pauses: ER-01 to ER-11 and FA-02 on the 10-13 close (R0), FA-01 and FA-03 to FA-05 on 10-14 (R0b), FA-06 to FA-13 on 10-15 (R0c). Both arms of each test always ran together.
  • Caveat
    ER-10 arm A accidentally ran a build script arm B had left in a shared scratch folder, then rebuilt its own outputs. The judge found none of B's distinctive figures in A's work. All later runs used private work folders.
  • Caveat
    Single run per arm, so there's no variance estimate beyond the control. The control showed zero difference, so the 16-point gap is unlikely to be noise, but per-test gaps of 1 point are within what a second run could flip.
  • Files
    Transcripts, deliverables, fixtures, keys, judge files and scorecard.md are in the results bundle (skill_comparison_2026-10-13.zip).
